- 日期：2026-11-14
- 状态：已实现
- 实施步骤与验收记录见[实施计划](../superpowers/plans/2026-11-14-tag-management.md)。

## 1. 背景与目标

现在的标签页（`/pages/tags`）只能浏览和搜索标签。新建标签只能在阅读页给文章加标签时顺带完成；删除只能先点进标签详情页再删。

用户想**先建好一批标签，之后再拿去给文章打**，并且希望**在标签列表页上直接删除**不需要的标签。

本次包含四项功能：

1. **新建标签**（标签列表页）：点击按钮，在弹出的对话框里填写名称、选择颜色。
2. **删除标签**（标签列表页）：在每张标签卡片上直接删除，删除前先确认。
3. **加标签时从已有标签里选**（阅读页和文库卡片）：现在只能手动输入名称，名称必须一字不差才会用上已有标签。改成输入时列出并筛选已有标签；没有匹配的名称时，可以直接按输入内容新建。
4. **编辑标签**（标签列表页，2026-11-15 追加）：在每张标签卡片上打开「编辑标签」对话框，修改名称和颜色。见第 3.6 节。

**成功标准：** 第 4 节的测试和验收全部通过。

### 1.1 用户已定的事项

- 新建标签使用**弹出对话框**（用户在示意图中选了 B）。创建成功后对话框关闭；要再建一个，需要重新点击按钮。
- 删除入口放在**标签列表页的卡片上**，不必进入详情页。
- **阅读页的加标签功能也纳入本次范围**：可以从已有标签中选择；输入的名称没有对应的已有标签时，支持直接输入新建。
- 加标签表单**浮在页面上方**，不放在卡片的文档流里，展开时文库卡片不会被撑高（2026-11-15）。
- **编辑标签**放在标签页卡片上：点「编辑」打开和新建相同的对话框，名称和颜色一起修改，点「保存」生效（2026-11-15。最初只做了点一下就保存的改色面板，加入改名后由用户改为合并成一个对话框）。
- 卡片上的编辑、删除按钮在电脑上悬停时**浮在卡片右侧**，不为它们预留空白（2026-11-15）。
- 用户确认的其余交互细节见第 3 节。

### 1.2 非目标

- 在阅读页、文库卡片或标签详情页编辑标签。
- 编辑时合并同名标签（改成已有的名称会被拒绝，不会合并两个标签的文章）。
- 一次删除多个标签。
- 在对话框里连续创建多个标签（用户选的是 B，不是“建完一个接着建下一个”的 A）。
- 修改后端 `AddTagToArticleCommandHandler` 按名称查找或创建标签的逻辑。前端选中已有标签时传入它的原名即可命中。
- 修改 `TagManager` 移除标签的方式，以及文库批量工具栏的「添加标签」「移除标签」。
- 修改标签详情页现有的删除按钮。
- 修复标签页搜索防抖的现有问题（`handleSearchChange` 返回的清理函数没有被调用）。

### 1.3 反目标（即使能用，出现这些也算失败）

- 点击卡片上的删除按钮时同时跳转到标签详情页。
- 创建同名标签时出现 500 错误、生成重复标签，或者对话框直接关闭、用户看不到原因。
- 删除标签时连带删除或修改文章本身（正文、状态、其他标签）。
- 删除标签后，已缓存的文库列表或订阅源列表仍然显示这个标签，直到手动刷新页面。
- 删除按钮在手机或触屏设备上因为依赖鼠标悬停而无法使用。
- 在阅读页选了已有标签，结果却新建了一个同名或只有大小写不同的标签。
- 输入 `go` 后按回车，加上的却是 `Gopher` 这类只是部分匹配的标签。
- 文库列表中每张卡片一挂载就请求一次全部标签。

## 3. 方案

### 3.1 后端：`POST /api/tags`

- **请求**：`{ "name": string, "color"?: string }`。
- **校验**：
  - `name` 去掉首尾空白后长度在 1 到 100 之间；
  - `color` 为空或省略时使用默认蓝色，否则必须是 `#RRGGBB`。
  - 不合法时返回 **400**，并附错误信息。
- **重名**：去掉首尾空白后，如果已有**完全相同**（区分大小写，与唯一索引一致）的名称，返回 **409**，响应体为 `{ "existingTagId": "<id>" }`。这与订阅源接口的 409 `{ existingFeedId }` 保持一致。
- **成功**：返回 **201**，响应体为 `TagWithArticleCountDto`，其中 `articleCount = 0`。`Location` 指向 `GET /api/tags/{id}`。
- **并发**：先查重再插入时，如果两个请求几乎同时提交，可能都通过查重，最后由唯一索引拒绝其中一个。这种情况也要返回 409，不能返回 500。
- 鉴权与 `TagsController` 的其他接口相同。
- 校验写在哪里（请求对象加 DataAnnotations，还是在 service 里返回结果）由实现者决定，但要和现有控制器的写法一致。

### 3.2 前端：新建对话框

- **入口**：标签页搜索框右侧加一个「新建标签」按钮（Arc `Button`，带 `Plus` 图标）。
  - 页面处于加载中或加载失败状态时，不显示这个按钮。
  - **列表为空时**（“还没有标签”）也要显示按钮，这正是用户先建标签的场景。空状态说明文字改为同时提示可以直接新建。
- **对话框**：使用 Arc `Dialog`，标题为「新建标签」。
  - 名称输入框（Arc `Input`，必填，`maxLength=100`，打开时自动聚焦）；
  - 颜色选择：10 种颜色，与 `TagManager` 相同，默认 `#3b82f6`。颜色列表抽成共享常量，`TagManager` 和对话框都从这里引用；
  - 底部按钮为「取消」和「创建」。
- **提交**：按回车或点击「创建」提交。
  - 名称去掉首尾空白后为空时，「创建」按钮不可用；
  - 提交期间，「创建」显示「正在创建…」，所有按钮和关闭操作都不可用。
- **成功**：
  - 关闭对话框，焦点回到「新建标签」按钮；
  - 重新加载标签列表：沿用当前搜索词调用 `tagApi.getTags`，所以新标签与搜索词不匹配时不会出现；
  - 列表只应用最新的搜索或创建后刷新响应，避免创建之前发出的请求覆盖新列表。
  - 弹出提示「已创建「X」」。
  - 每次打开对话框时，名称和颜色都重置为默认值。
- **失败**：对话框保持打开，已输入的内容保留，在输入框下方用 `role="alert"` 显示错误：
  - 409：「已有同名标签」；
  - 400：显示后端返回的信息，没有时显示「标签名称无效」；
  - 其他错误：「创建失败，请重试」。
- `tagApi` 增加 `createTag(name, color)`，返回 `TagWithArticleCount`。

### 3.3 前端：卡片上的删除

- 卡片由“整张卡片是一个 `<Link>`”改为：外层容器里放两个并列元素，一个是 `<Link>`（色点、名称、篇数），一个是删除按钮。删除按钮**不能放在链接里面**。
- **删除按钮**：
  - 只有图标（`Trash2`），`aria-label="删除标签「X」"`；
  - 电脑上，鼠标悬停卡片或焦点进入卡片（`:focus-within`）时显示；
  - 宽度不超过 600px 的屏幕和触屏设备（`@media (hover: none)`）上始终显示，点击区域至少 44px。这与批量工具栏现有的触屏规则一致。
- **确认**：调用 `useConfirm()`，标题为「删除标签」，确认按钮为「删除标签」。提示文字：
  - `articleCount > 0`：「删除「X」标签？它会从 N 篇文章中移除，文章本身不受影响。」
  - `articleCount = 0`：「删除「X」标签？」
- **确认后**：
  - 调用 `tagApi.deleteTag`；
  - 成功后从页面状态中移除这个标签（不必重新请求），然后调用 `notifyLibraryMutation()`，让文库缓存和订阅源列表不再显示这个标签；
  - 列表过滤当前页面已删除的标签 ID，避免删除前发出的请求返回后把卡片重新显示出来。
  - 失败时 `toast.show("标签删除失败，请重试。")`，标签保留在列表中。
  - 请求进行中，这张卡片的删除按钮不可用，防止重复点击。
- 顶部的「N 个标签 / N 篇文章」统计跟着页面状态一起更新。

### 3.4 前端：加标签时从已有标签里选（`TagManager`）

阅读页和文库卡片共用 `TagManager`，两处同时生效。已加标签的展示和移除方式不变。

- **展开**：点击「添加标签」后，整个表单在按钮下方的浮层（Arc `Popover`）中打开，不占卡片的文档流，文库卡片和同一行的其他卡片高度不变。按钮保持显示，`aria-expanded` 表示浮层是否打开；点击浮层外部或按 Esc 等同于「完成」。名称输入框改为可搜索的下拉选择（ARIA combobox）：
  - 输入框带 `role="combobox"`、`aria-expanded`、`aria-controls`、`aria-activedescendant`，下拉列表为 `role="listbox"`，每项为 `role="option"`；
  - 占位文字为「搜索或新建标签…」；
  - `maxLength` 从 20 改为 100，与后端一致；
  - 展开时自动聚焦。
- **加载**：每次展开时调用一次 `tagApi.getTags()`。
  - 加载中，列表显示「正在加载标签…」；
  - 等待加载结果后再开放新建，避免已有名称被当作新标签提交。
  - 加载失败，列表显示「标签加载失败」，但仍可以输入名称新建。
  - 文库卡片只在展开表单时才加载，不会每张卡片挂载时都发请求。
- **列表内容**：本文**还没加上的**全部已有标签，顺序与接口返回一致（按名称排序）。每项显示色点和名称。
  - 输入时按名称**不区分大小写的包含**关系筛选，输入内容先去掉首尾空白；
  - 筛选后没有可选的已有标签时，显示「没有匹配的标签」。名称与本文已加的标签完全匹配时，空列表优先显示「已添加」。
  - 列表区域最多约 240px 高，超出部分滚动。
- **新建选项**：输入去掉首尾空白后非空，并且**所有**已有标签（包括本文已加的）中都没有与它**不区分大小写完全相同**的名称时，列表末尾出现「创建「X」」选项，同时在列表下方显示「新标签颜色」。颜色选择沿用现在的 10 种颜色和「自定义」，默认 `#3b82f6`。其他情况下不显示新建选项，也不显示颜色选择。
- **已加过的标签**：输入与本文已加的某个标签不区分大小写完全相同时，列表显示不可选的提示「已添加」。直接按回车不会提交。用方向键高亮另一个候选项后按回车，会选择该候选项。
- **键盘与鼠标**：
  - 默认没有高亮项。↑↓ 在可选项之间移动高亮，范围包括已有标签和新建选项；
  - 回车：有高亮项时选中它；没有高亮项时，如果有与输入不区分大小写完全相同、且本文还没加上的已有标签，就加上它，否则按输入内容新建；
  - 点击选项与回车选中的效果相同；
  - 输入法组字期间，回车用于确认输入，Esc 用于取消组字，都不会提交或关闭表单。
  - 修改输入内容会清除高亮；
  - Esc 等同于「完成」。
  - 表单中的主按钮仍为「添加」，效果与“没有高亮项时按回车”相同；名称为空、已添加或请求进行中时不可用。
- **选中已有标签**：调用 `articleApi.addTag(articleId, { name: 已有标签的原名, color: 已有标签的颜色 })`。后端按原名精确命中，不会新建标签。
- **新建**：调用 `articleApi.addTag(articleId, { name: 去掉首尾空白后的输入, color: 所选颜色 })`。
- **成功后**：
  - 调用 `onTagsChange([...tags, 返回的标签])`；
  - 清空输入、颜色恢复为默认值、清除高亮，表单**保持展开**，焦点留在输入框，可以接着加下一个；
  - 新建的标签加入本地的已有标签列表，不必重新请求。
  - 原来的「取消」按钮改名为「完成」，点击后收起表单。
- **失败**：提示「添加标签失败，请重试」（沿用现有文案），保留输入内容。
- **请求进行中**：输入框、选项和按钮都不可用，防止重复添加。

### 3.5 文档

在 `CLAUDE.md` 的 API Structure 中加入 `POST /api/tags`、`PUT /api/tags/{id}` 和 `DELETE /api/tags/{id}`。说明标签页可以新建、编辑和删除标签，以及阅读页和文库卡片加标签时可以从已有标签里选。

### 3.6 编辑标签（2026-11-15 追加）

- **后端**：`PUT /api/tags/{id}`，请求体 `{ name, color }`，两个字段都必填。
  - 名称规则与新建相同：去掉首尾空白后 1–100 个字符，**区分大小写**判断重名；颜色必须是 `#RRGGBB`（只接受 ASCII 十六进制）。不合法时返回 400 `{ error }`，标签不变。
  - 新名称被另一个标签占用时返回 409 `{ existingTagId }`，标签不变；名称不变只改颜色、或只改大小写，都可以保存。
  - 两个请求同时把不同标签改成同一个名称时，只有一个成功，另一个返回 409（由数据库唯一索引兜底，与新建共用 `TagWriter` 的冲突处理）。
  - 成功返回 204；标签不存在返回 404；文章关联不变。未登录的请求被拒绝。
- **前端**：`tagApi.updateTag(id, name, color)`。
  - 每张卡片在删除按钮左边加一个「编辑」按钮（`Pencil` 图标，`aria-label="编辑标签「X」"`），放在链接外面。
  - 点击后打开 `TagDialog` 的编辑模式：标题「编辑标签」，名称和颜色预填为当前值（颜色不区分大小写匹配预设），主按钮「保存」（进行中显示「正在保存…」）。
  - 409 时对话框保持打开，显示「已有同名标签」；其他失败显示「保存失败，请重试」。
  - 成功后关闭对话框，立即更新卡片，调用 `notifyLibraryMutation()` 让文库卡片上的标签名称和颜色跟着更新，再按当前搜索词重新加载列表以恢复排序。焦点回到这张卡片的「编辑」按钮；改名可能让卡片换到另一个字母分组，所以由页面在列表更新后重新聚焦。
- **卡片按钮的排版**：
  - 电脑（`(hover: hover) and (pointer: fine)` 且宽度大于 600px）上，编辑和删除按钮绝对定位在卡片右侧，平时隐藏，悬停或焦点进入卡片时显示，左边缘用渐变过渡到卡片背景，不占用排版空间。
  - 触屏和窄屏上按钮留在行内、始终显示，点击区域至少 44px。
- **共享颜色按钮的选中状态**用 `box-shadow` 画圈，不用 `outline`：`foundation.css` 会去掉鼠标点击后获得焦点的按钮的 `outline`，用 `outline` 时刚点的颜色要等焦点移开才显示选中。

## 5. 我自己做的决定（请重点核对）

- 重名判断区分大小写，与数据库唯一索引一致：`Go` 和 `go` 可以同时存在。
- 409 响应体带 `existingTagId`，与订阅源接口保持一致。
- 创建成功后弹出「已创建「X」」提示，并重新加载列表，而不是在本地插入新标签。
- 删除成功后不显示撤销：删除标签是永久操作，确认对话框已经说明影响。
- 确认文字里的篇数不包含回收站里的文章，订阅源默认标签被一并移除也不单独提示；`articleCount` 本身就不统计回收站。
- 颜色列表抽成共享常量，标签页对话框和 `TagManager` 都引用它。标签页对话框只提供 10 种颜色；`TagManager` 保留「自定义」取色器。
- 空状态下也显示「新建标签」按钮，并修改说明文字。
- 阅读页的下拉选择**不区分大小写**判断“同名”：已有 `Go` 时输入 `go`，加上的是 `Go`，不会新建。这样可以避免先建好的标签因为大小写不同又被重复创建。标签页对话框和 API 仍然区分大小写，与数据库唯一索引一致。
- 输入后默认不高亮任何选项，避免输入 `go` 后按回车却加上了 `Gopher`。
- 加上一个标签后表单保持展开，方便连续添加；「取消」改名为「完成」。这改变了现在“加完就收起”的行为。
- `TagManager` 的名称长度上限从 20 改为 100，与后端一致，这样标签页建的长名称也能在阅读页输入。
- 阅读页和文库卡片同时改，因为它们共用 `TagManager`。
- 浮层里放的是整个加标签表单，而不只是下拉列表：只让列表浮起来会盖住下方的颜色选择和「添加」「完成」按钮。
- 编辑成功返回 204 而不是标签对象：前端已经知道新名称和颜色，随后的列表重新加载会带回服务端排序。
- 编辑用 `PUT` 并要求名称和颜色都提供：对话框总是同时提交两者，不需要部分更新。
