MiniCC 有两种运行方式。自己日常使用，选 Compose；要改代码，再从源码运行。

## 用 Compose 部署（推荐）

需要 [Podman](https://podman.io/) 和 `podman compose`，或者 Docker 和 Docker Compose。用 Docker 的话，把下面命令里的 `podman compose` 换成 `docker compose`。

<Steps>

1. 克隆仓库。

   ```bash
   git clone https://github.com/zxyao145/mini-cc.git
   cd mini-cc
   ```

2. 选一个数据库启动。两者的区别见下文的[选择数据库](#选择数据库)。

   <Tabs syncKey="database">
     <TabItem label="PostgreSQL">
       ```bash
       podman compose -f deploy/docker-compose.yaml up -d --build
       ```
     </TabItem>
     <TabItem label="SQLite">
       ```bash
       podman compose -f deploy/docker-compose.sqlite.yaml up -d --build
       ```
     </TabItem>
   </Tabs>

3. 打开 [http://localhost:5000](http://localhost:5000)，按[首次登录](#首次登录)的说明登录。

</Steps>

几点说明：

- 5000 端口通过 nginx 同时提供 Web 应用和 API。PostgreSQL 版还会把数据库映射到主机的 15432 端口，密码是 `postgres`。主机要暴露到外网之前，请在 `deploy/docker-compose.yaml` 里改掉密码，或者删掉这个端口映射。
- 数据保存在命名卷里：PostgreSQL 版用 `pgdata` 和 `api-data`，SQLite 版用 `sqlite-data`。本地图片和登录 Cookie 的加密密钥也在 API 的数据卷里。
- 两个 Compose 文件使用相同的容器名。要换数据库，先用当前那份 Compose 文件执行 `down`，再启动另一份。

### 换成自己的域名

Web 应用在构建时写入 API 地址，默认是 `http://localhost:5000/api`。要通过其他主机名或域名访问，修改 Compose 文件里 `minicc-web` → `build.args` 下的 `NEXT_PUBLIC_API_URL`，例如：

```yaml
minicc-web:
  build:
    args:
      NEXT_PUBLIC_API_URL: https://minicc.example.com/api
```

改完后需要重新构建，也就是再执行一次带 `--build` 的 `up` 命令。

## 选择数据库

| | PostgreSQL | SQLite |
| --- | --- | --- |
| 运行方式 | 独立的数据库容器（zhparser 镜像） | API 数据卷里的一个文件 |
| 搜索 | zhparser 中文分词，加标题子串匹配 | 在标题、摘要、作者和 HTML 正文里做子串匹配 |
| 适合 | 大多数部署，尤其是中文内容多的文章库 | 只跑一个 API 实例、数据放在本地磁盘的部署 |

用 SQLite 时要注意：

- 搜索忽略 ASCII 字母大小写。因为是在 HTML 正文里匹配，标签和 HTML 实体也可能影响结果。
- 标签名和订阅源标题按二进制顺序排序。
- 数据库要放在本地磁盘或本地命名卷上。SQLite 运行在 WAL 模式下。

## 从源码运行

需要：

- .NET 10.0 SDK
- Node.js 22.13 及以上，pnpm 12.5.1（`npm install -g pnpm@12.5.1`）
- 使用 PostgreSQL 时，需要装有 zhparser 的 PostgreSQL 16

<Steps>

1. 在仓库根目录安装依赖。

   ```bash
   pnpm install --frozen-lockfile
   ```

2. 启动 API。图片默认存到 `src/server/data/images`，经 API 提供。Web 开发服务器跑在 4000 端口，所以要把 `Images__ApiUrl` 设成 API 的完整地址，页面才能加载本地图片。

   <Tabs syncKey="database">
     <TabItem label="PostgreSQL">
       ```bash
       cd src/server
       export MiniCC_Db="Host=127.0.0.1;Database=mini_cc;Username=postgres;Password=your_password"
       export Images__ApiUrl="http://localhost:5001/api/images"
       dotnet run
       ```
     </TabItem>
     <TabItem label="SQLite">
       ```bash
       cd src/server
       Database__Provider=sqlite Images__ApiUrl=http://localhost:5001/api/images dotnet run
       ```
     </TabItem>
   </Tabs>

   API 启动时会初始化 zhparser（PostgreSQL），或者创建 `src/server/data/mini_cc.db`（SQLite），然后执行数据库迁移。它监听 [http://localhost:5001](http://localhost:5001)。

   API 默认的 PostgreSQL 连接串和 Compose 里的数据库一致。只想跑一个数据库容器的话，执行 `podman compose -f deploy/docker-compose.yaml up -d db`，就不用再设置 `MiniCC_Db`。

3. Web 应用默认请求 `http://localhost:5001/api`。API 在别的地址时，在 `src/web/.env.local` 里写上实际地址，例如：

   ```dotenv
   NEXT_PUBLIC_API_URL=http://192.168.1.20:5001/api
   ```

4. 在仓库根目录执行 `pnpm dev`，打开 [http://localhost:4000](http://localhost:4000)。

</Steps>

## 首次登录

第一次启动会创建一个账号，用户名 `mini_cc`，密码 `mini_cc_password`。MiniCC 没有注册页面。

登录后点侧边栏底部的账户，在**个人资料**标签页里修改用户名和密码。改密码之后，这个账号在其他浏览器上的登录会全部失效。

登录时勾选**记住我**，登录状态保留 30 天；不勾选的话，30 分钟没有操作就需要重新登录。两种情况下，只要一直在用，有效期都会自动顺延。
