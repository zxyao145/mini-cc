MiniCC 支持两种运行方式：日常自用推荐直接上 Compose，省心省力；如果要二次开发或改代码，再从源码启动。

## 用 Compose 部署（推荐）

发布镜像适用于 Linux amd64。部署主机需要安装 Docker Compose，或安装 [Podman](https://podman.io/) 并配置支持 `pull` 和 `up -d --no-build` 的 Compose 提供程序。

<Steps>

1. 在 [GitHub Releases](https://github.com/zxyao145/mini-cc/releases) 下载所选版本的 **Source code** 压缩包，解压后进入含有 `deploy/` 的目录。命令中的 `MINICC_VERSION` 应与所选 Release 标签一致。

2. 按需选一种数据库启动服务（两者的取舍可以参考下文的[选择数据库](#选择数据库)）：

   <Tabs syncKey="database">
     <TabItem label="SQLite">
       <InstallCommand database="sqlite" />
     </TabItem>
     <TabItem label="PostgreSQL">
       <InstallCommand database="postgres" />
     </TabItem>
   </Tabs>

3. 浏览器打开 [http://localhost:5000](http://localhost:5000)，按照[首次登录](#首次登录)里的说明登录即可。

</Steps>

部署前有几点需要留意：

- 5000 端口经由 nginx 同时提供 Web 应用和 API。PostgreSQL 版把数据库映射到宿主机的 15432 端口，默认密码为 `postgres`。对外开放部署前，在 `deploy/docker-compose.yaml` 中收紧或移除数据库端口映射，并同步修改 `POSTGRES_PASSWORD` 和 `MiniCC_Db` 中的密码。
- 所有持久化数据都存放在命名卷中：PostgreSQL 版使用 `pgdata` 和 `api-data`，SQLite 版使用 `sqlite-data`。本地保存的文章图片，以及加密登录 Cookie 的密钥，也一并存在 API 的数据卷里。
- 切换数据库前，用当前的基础 Compose 文件、GHCR 覆盖文件和当前版本执行 `down`，保留数据卷。需要沿用已有数据时，先安排跨库迁移。

### 换成自己的域名

发布版 Web 镜像通过当前访问地址的 `/api` 请求 API。使用局域网地址或自定义域名时，把 Web 和 `/api/` 一起转发到 MiniCC 的 nginx 即可。

## 选择数据库

| | PostgreSQL | SQLite |
| --- | --- | --- |
| 运行方式 | 独立的数据库容器（内置 zhparser） | API 数据卷里的单个数据库文件 |
| 搜索能力 | zhparser 中文分词，辅以标题子串匹配 | 对标题、摘要、作者和 HTML 正文做子串匹配 |
| 适用场景 | 大多数部署，尤其是中文文章较多的用户 | 单实例轻量部署，数据放在本地磁盘上 |

使用 SQLite 时有几个细节需要注意：

- 搜索不区分 ASCII 字母大小写。因为直接匹配 HTML 正文，标签名和 HTML 实体有时也会被搜到。
- 标签名和订阅源标题按二进制顺序排列。
- SQLite 运行在 WAL 模式下，数据库文件请务必放在本地磁盘或本地命名卷上，不要放在网络文件系统里。

## 从源码运行

本地开发需要准备以下环境：

- .NET 10.0 SDK
- Node.js 22.13 及以上版本，以及 pnpm 12.5.1（可通过 `npm install -g pnpm@12.5.1` 安装）
- 如果选用 PostgreSQL，需要装有 zhparser 扩展的 PostgreSQL 16

<Steps>

1. 在仓库根目录安装工作区依赖：

   ```bash
   pnpm install --frozen-lockfile
   ```

2. 启动 API 服务。图片默认保存在 `src/server/data/images` 目录并由 API 提供访问。由于前端开发服务器跑在 4000 端口，需要把 `Images__ApiUrl` 设为 API 的完整地址，页面才能正常加载本地图片。

   <Tabs syncKey="database">
     <TabItem label="PostgreSQL">
       ```bash
       cd src/server
       export MiniCC_Db="Host=127.0.0.1;Database=mini_cc;Username=postgres;Password=your_password"
       export Images__ApiUrl="http://localhost:5001/api/images"
       dotnet run
       ```
     </TabItem>
     <TabItem label="SQLite">
       ```bash
       cd src/server
       Database__Provider=sqlite Images__ApiUrl=http://localhost:5001/api/images dotnet run
       ```
     </TabItem>
   </Tabs>

   API 启动后会自动初始化 zhparser（PostgreSQL）或创建 `src/server/data/mini_cc.db`（SQLite），并完成数据库迁移，随后监听在 [http://localhost:5001](http://localhost:5001)。

   API 内置的默认 PostgreSQL 连接串与 Compose 中的数据库配置一致。如果你只想用容器跑一个数据库，执行 `podman compose -f deploy/docker-compose.yaml up -d db` 即可，连 `MiniCC_Db` 都不用手动配。

3. Web 应用默认请求 `http://localhost:5001/api`。如果 API 跑在别的地址，在 `src/web/.env.local` 里指定实际地址：

   ```dotenv
   NEXT_PUBLIC_API_URL=http://192.168.1.20:5001/api
   ```

4. 回到仓库根目录执行 `pnpm dev`，打开 [http://localhost:4000](http://localhost:4000) 即可访问。

</Steps>

## 首次登录

系统首次启动时会自动创建一个默认账号，用户名 `mini_cc`，密码 `mini_cc_password`。MiniCC 本身不提供公开注册页面。

登录后，点击侧边栏底部的账户入口，在**个人资料**标签页里尽快修改用户名和密码。修改密码后，该账号在其他浏览器上的登录会话会立刻全部失效。

登录时勾选**记住我**，登录状态可保持 30 天；不勾选的话，连续 30 分钟无操作就需要重新登录。无论哪种方式，只要你还在持续使用，会话有效期都会自动顺延。
