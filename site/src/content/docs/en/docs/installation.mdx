You can run MiniCC in two ways: use Compose for everyday self-hosting, or run from source if you plan to modify the code.

## Deploy with Compose (recommended)

Release images target Linux amd64. Install Docker with Docker Compose, or [Podman](https://podman.io/) with a Compose provider that supports `pull` and `up -d --no-build`.

<Steps>

1. Download the **Source code** archive for your version from [GitHub Releases](https://github.com/zxyao145/mini-cc/releases). Extract it and open the directory containing `deploy/`. Set `MINICC_VERSION` in the command to the matching release tag.

2. Start the stack with your chosen database. See [Choosing a database](#choosing-a-database) if you are not sure which to pick.

   <Tabs syncKey="database">
     <TabItem label="SQLite">
       <InstallCommand database="sqlite" />
     </TabItem>
     <TabItem label="PostgreSQL">
       <InstallCommand database="postgres" />
     </TabItem>
   </Tabs>

3. Open http://localhost:5000 and follow [First sign-in](#first-sign-in).

</Steps>

A few things to keep in mind:

- Port 5000 serves both the web app and the API behind nginx. PostgreSQL also exposes the database on host port 15432 with the password `postgres`. Before exposing the host, restrict or remove that port mapping and update the password in both `POSTGRES_PASSWORD` and `MiniCC_Db` in `deploy/docker-compose.yaml`.
- Persistent data is stored in named volumes: `pgdata` and `api-data` for PostgreSQL, or `sqlite-data` for SQLite. Locally stored images and the encryption keys for sign-in cookies live in the API data volume as well.
- Before switching databases, run `down` with your current base Compose file, GHCR override and version, and keep the volumes. Plan a database migration if you need to move your data between engines.

### Serve MiniCC from your own domain

The published web image calls `/api` on the same origin as the page. For a LAN address or custom domain, route both the web app and `/api/` through MiniCC's nginx.

## Choosing a database

| | PostgreSQL | SQLite |
| --- | --- | --- |
| Setup | Separate database container (zhparser image) | Single file inside the API data volume |
| Search | Chinese word segmentation via zhparser, plus title substring matching | Substring matching across title, summary, author, and HTML body |
| Best for | Most setups, especially libraries with Chinese articles | Lightweight single-instance setups on a local disk |

Keep a few SQLite quirks in mind:

- Search is case-insensitive for ASCII letters. Because it searches the raw HTML body, markup and HTML entities can occasionally show up in matches.
- Tag names and feed titles sort in binary order.
- SQLite runs in WAL mode, so keep the database file on a local disk or local named volume rather than a network share.

## Run from source

Prerequisites:

- .NET 10.0 SDK
- Node.js 22.13 or later and pnpm 12.5.1 (`npm install -g pnpm@12.5.1`)
- PostgreSQL 16 with zhparser, if you are using PostgreSQL

<Steps>

1. Install workspace dependencies from the repository root:

   ```bash
   pnpm install --frozen-lockfile
   ```

2. Start the API. Images are saved under `src/server/data/images` by default and served by the API. Because the web dev server runs on port 4000, set `Images__ApiUrl` to the full API address so pages can load local images.

   <Tabs syncKey="database">
     <TabItem label="PostgreSQL">
       ```bash
       cd src/server
       export MiniCC_Db="Host=127.0.0.1;Database=mini_cc;Username=postgres;Password=your_password"
       export Images__ApiUrl="http://localhost:5001/api/images"
       dotnet run
       ```
     </TabItem>
     <TabItem label="SQLite">
       ```bash
       cd src/server
       Database__Provider=sqlite Images__ApiUrl=http://localhost:5001/api/images dotnet run
       ```
     </TabItem>
   </Tabs>

   On startup, the API initializes zhparser (PostgreSQL) or creates `src/server/data/mini_cc.db` (SQLite), applies migrations automatically, and listens on http://localhost:5001.

   The API's default PostgreSQL connection string matches the Compose database. If you only want a containerized database, run `podman compose -f deploy/docker-compose.yaml up -d db` and omit `MiniCC_Db`.

3. The web app talks to `http://localhost:5001/api` by default. If your API runs elsewhere, set its URL in `src/web/.env.local`:

   ```dotenv
   NEXT_PUBLIC_API_URL=http://192.168.1.20:5001/api
   ```

4. Run `pnpm dev` from the repository root and open http://localhost:4000.

</Steps>

## First sign-in

On first startup, MiniCC creates a single account with username `mini_cc` and password `mini_cc_password`. There is no sign-up page.

Once signed in, click your account at the bottom of the sidebar and update both the username and password on the **个人资料** (Profile) tab. Changing the password immediately signs out all other browsers.

Check **记住我** (Remember me) at sign-in to stay logged in for 30 days; otherwise the session expires after 30 minutes of inactivity. Either way, the expiration slides forward as long as you keep using MiniCC.

Next: [install the browser extension](/en/docs/extension/).
